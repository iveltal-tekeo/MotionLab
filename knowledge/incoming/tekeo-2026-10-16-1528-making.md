- [local-make-3] (2026-10-15, from What's new in MotionLab 0.4.3 v1) In a talking video cut from several takes, level
  the voice per shot before the sound effects: measure each shot's RMS, bring it to one target (-26 dBFS), cap the
  gain so no peak passes -1 dBFS, then run `sfx.py plan` (with `--song-db 0`, the voice is not a song to duck).

- [local-make-6] (2026-10-15, from test_0.4.5_motionlab_graphics whats_new_045, the final render) A HyperFrames render
  longer than the chat tool's 10-minute limit (a 900-frame 1080x1920 reel with motion blur 5 = 4500 sub-frames) must
  run detached WITH the variable HYPERFRAMES_RENDER_DETACHED=1 in its environment: HyperFrames 0.8.149 polls every
  ancestor process every 2 s and cancels the render ("render_cancelled_parent_exited") when any of them ends - the
  Claude Code session, the tool's shell, a launcher. Launch from PowerShell (the variable set there is inherited;
  cmd's `set X=1 && ...` sets "1 " with a trailing space and HyperFrames ignores it): `$env:HYPERFRAMES_RENDER_DETACHED
  = "1"; Start-Process C:\MotionLab\.venv\Scripts\python.exe -ArgumentList "tools\overlay.py", "render", "<folder>",
  "--mp4", "--motion-blur", "5" -WorkingDirectory C:\MotionLab -WindowStyle Hidden -RedirectStandardOutput <log>
  -RedirectStandardError <err> -PassThru`, then watch the process id (tasklist) and read the log. The app's jobs are
  fine (the server stays alive).
  Why: four renders in a row were cancelled within seconds (a background Bash killed with the session, two detached
  launches with the variable missing / mis-set) before the cause was read in HyperFrames' code.   Tool: the launch
  above

- [local-make-8] (2026-10-16, from the motion template kinetic-stack f0-f146 (00:00:00:00-00:00:04:26)) In a HyperFrames
  graphic, never put two sets of the same property on the same frame - in particular "hidden from frame 0" plus
  "shown at the start frame" when the start frame is 0: HyperFrames' snapshot / render kept the element hidden on
  EVERY frame (a browser seeking the same timeline showed it). Hide before the start only when the start is after

- [local-make-9] (2026-10-16, from the Swishy pack: 120 captured motion-graphics clips, 500 moves, measured by
  `templates.py read`) The motion rules of designed motion graphics, in numbers (at 25 fps; x1.2 at 30): something moves
  within 2 frames of the start (median; 75 % within 17 f) - never open on a still frame; a move lasts 11 f (median;
  6-29 f for the middle half, 55 f at most for 90 %); its ease is an S-curve (60 % of moves) or decelerating / slow end
  (29 %) - accelerating only for exits and drops (8 %), linear almost never (3 %, clocks and tickers); a hold lasts
  17 f (median; 31 f for 75 %, 54 f for 90 %), and in half the clips something still moves during it (a drift, a
  pulse, a blink); the frame is moving 42 % of the time. Write graphics to these numbers and check a snapshot sheet
  against them: a hold over ~2 s with nothing alive, or a 30-frame linear move, is the "dull" the user rated.
  Why: the user rated MotionLab's graphics "dull, very simple"; these are the measured habits of the clips they chose
  as good.   Tool: `templates.py show <pack>` / `analysis\templates\<pack>\pack.json`; the motion templates in
  `tools\overlays\motion\` follow them
- [local-make-10] (2026-10-16, from building the 25 motion templates) Four bugs that cost a snapshot round each, all
  invisible in the code: (1) an element whose entrance starts after frame 0 shows in its END pose until then - `ft`
  sets its start pose only at the entrance frame; hide it from frame 0 (`enter()` in the motion templates; also for
  scale / dash-offset entrances: `set(e, {scaleY: 0}, 0)`); (2) a font name in an inline `style="font: ... "Inter"..."`
  attribute ends the attribute at its quote - set fonts with `Object.assign(e.style, ...)`; (3) a CSS rule later in the
  sheet with the same weight (`.cur {display: inline-block}` after `.c {display: none}`) silently wins; (4) newer emoji
  (🫡) are missing from the render's emoji font - use long-standing ones. And: in the Bash tool a heredoc eats one level
  of backslashes - a JS regex `\n` patched through it became a real line break; write patch scripts with the Write tool.
  Why: each showed as a wrong sheet (a bar chart full at f0, a serif badge, green bars under every letter, a box for
  the emoji, a broken split).   Tool: `templates.py check <id> [--values JSON]`
  (5, the same day, stretch-pills) A top-level `const top = ...` (top, location, document, window: the window
  properties that cannot be replaced; `origin`, `name`, `status` are replaceable and work - speech-bubble's `const
  origin` renders - but avoid them too) makes the WHOLE script fail before its first line - a global lexical
  declaration clashing with `window.top` - and HyperFrames then draws an empty frame with no error in its log; a browser
  test that wraps the script in `try {}` hides it (block scope). Name it `top0` / `ctop`, or keep it inside a block. A
  frame with nothing at all (not even the background colour) = the script never ran: look for this first.
  (6, the same day, the 17 templates from the marketplace research) (2) again, in four templates at once: a font stack
  built as `"${V.font}", "Segoe UI"` and put into an `innerHTML` style attribute - write font stacks with single quotes
  (`'${V.font}', 'Segoe UI', sans-serif`), they work in both places. And a scale whose transform origin lies far outside
  the element (a radial bar turned around the ring's centre) also moves the element toward that origin as it shrinks:
  the bars sank under the picture. A holder takes the turn, the bar inside scales from its own foot.
  The self-test's snapshot of every template (--extended) catches it.
